### Angelo Kamachi (2026-10-07T00:25:50.815Z)

FIX: Lalamove connected status strip overflows on narrow viewports

FILE: src/pages/home/Shipping/components/LalamoveConnect.jsx
COMMIT: 8a960a070 (branch refactor/tw-settings-standard-v3)
ON DEV VIA: PR #8748 (refactor/tw-settings-standard-v3-dev6)

SYMPTOM
At 390px the status strip overflows its card to the right. The sentence clips at "are veri"; connection.pubKey clips mid-token. Measured overflow approx 100px past the card edge.

MARKUP BEFORE

  <div class="d-flex flex-wrap align-items-start justify-content-between gap-3 bg-table rounded-3 p-3">
    <div>                                          <- text column, flex item
      <div class="d-flex align-items-center gap-2 mb-1">
        <span class="badge bg-success">Connected</span>
        <span class="text-sm fw-semi-bold text-black">Your API keys are verified and in use.</span>
      </div>
      <div class="text-sm text-muted">
        Public key: <span class="font-monospace">{connection?.pubKey}</span>
      </div>
    </div>
    <AppButton>Disconnect</AppButton>
  </div>

ROOT CAUSE - three independent faults

1. Text column cannot shrink.
   The column is a flex item of the outer .d-flex. Per CSS Flexbox, a flex item's min-width computes to auto, which floors its used width at min-content (effectively max-content here, since the children below cannot wrap). The column therefore never shrinks to the card width; it keeps its content width and overflows. The outer flex-wrap does not help: the column is a single item, so there is no wrap opportunity between it and the button until the column itself can shrink.

2. Badge row cannot wrap.
   The inner row is .d-flex with no wrap utility, so flex-wrap resolves to its initial value nowrap. The badge and the sentence are therefore locked on one line, and that line's width is what sets the column's max-content width in fault 1.

3. pubKey has no break opportunity.
   connection.pubKey is a single token with no spaces or hyphens (pk_test_8c95f6e1841041d9c5...). With the initial overflow-wrap: normal, the UA has no soft wrap opportunity inside the token, so it renders on one line regardless of container width.

DIFF

  - <div>
  + <div class="tw:min-w-0 tw:flex-1">

  -   <div class="d-flex align-items-center gap-2 mb-1">
  +   <div class="d-flex flex-wrap align-items-center gap-2 mb-1">

  -   <div class="text-sm text-muted">
  +   <div class="text-sm text-muted text-break">
  -     <span class="font-monospace">{connection?.pubKey}</span>
  +     <span class="font-monospace text-break">{connection?.pubKey}</span>

WHAT EACH DECLARATION DOES

  tw:min-w-0   -> min-width: 0
                 Overrides the auto floor from fault 1 so the column may shrink below its content width.
  tw:flex-1    -> flex: 1 1 0%
                 flex-basis 0 plus grow, so the column is sized by available space rather than content, and shrink is permitted.
  flex-wrap    -> flex-wrap: wrap (Bootstrap utility)
                 Gives the badge/sentence row a wrap opportunity; the sentence drops to a second line when the row no longer fits.
  text-break   -> word-wrap: break-word; word-break: break-word (Bootstrap utility, _utilities.scss "word-wrap" key)
                 Creates a break opportunity inside pubKey so it wraps instead of overflowing.

Faults 1 and 2 are coupled: fixing either alone is insufficient. min-w-0 without flex-wrap lets the column shrink but the nowrap row then overflows the column. flex-wrap without min-w-0 permits wrapping but the column never shrinks to a width that forces it.

NOT CHANGED
- Desktop layout: at >=768px the column's content fits, so min-width:0 and the wrap utilities are never exercised. No visual delta.
- .badge bg-success keeps its colour; it is a separate element from the status text.
- The Prosperna-managed Lalamove strip (shown when BYO keys are not connected) is a different branch of this component and was not touched.
- Disconnect button markup unchanged; it regains its position as a consequence of the column shrinking, not by its own change.

VERIFICATION
ESLint clean. 9 test files / 93 tests pass on the affected components (the existing LalamoveConnect suite included). Layout overflow is not observable in jsdom - no test asserts the fix. Confirmation requires a 390px viewport; see the test-case comment on this task.
