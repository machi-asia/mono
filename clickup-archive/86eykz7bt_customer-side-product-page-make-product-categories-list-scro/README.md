## Description

Description:
The list of product categories is currently cut off, preventing users from seeing or selecting the final 6 categories. A scrollable container needs to be implemented so all categories are accessible.

Expected Result:
The product category container allows vertical scrolling (or features an overflow-y scrollbar) so users can scroll down and view all remaining product categories, including the hidden 6.

Actual Result:
The product category container is fixed in height or missing proper overflow styling, hiding the remaining 6 categories with no way for the user to scroll down to see them.

2. WHAT CHANGED & WHY IT NEEDED CHANGING
============================================================
Based on findings across QA re-tests and technical code review:

1. Dynamic Dropdown Height Capping & 80vh Override:
   - Why: A static 80vh cap was overshooting short desktop viewports / zoomed layouts and artificially capping lists that could naturally fit.
   - What Changed: Dynamically calculates available viewport height below the nav bar (window.innerHeight - top - 16px) and sets inline max-height: none when lists fit naturally.

2. Flyout Panel Suspension & Ancestor Traversal:
   - Why: When a parent menu has overflow-y: auto, browsers enforce overflow-x: auto, which strictly cut off child flyouts opening horizontally beyond the 250px panel box (Staging Cases #9 & #10).
   - What Changed: When a child flyout (.dropdown-menu.show) opens, capping is suspended on all ancestor menus (overflow-y: visible; max-height: none). The MutationObserver walks ancestors on both open and close transitions.

3. Scrolled Flyout Counter-Shift (Margin-Top & Scroll Restoration):
   - Why: Switching overflow-y to visible reset scrollTop to 0, which shifted rows down, caused rapid 0.2s open/close flickering, and lost the user's scroll position upon hover.
   - What Changed: Applies marginTop: -savedScrollTop px on .navbar-nav during suspension to hold rows physically steady. When the child flyout closes, reads savedScrollTop into a dedicated local variable before dataset deletion, and restores menu.scrollTop cleanly.

4. Scrolled-Away Rows Clipping (-5000px Inset):
   - Why: Uncapping overflow-y with negative marginTop exposed scrolled-away rows (items 1-5) above the menu and across the header. An initial clip-path: inset(offset 0 0 0) prevented that but clipped child flyouts to the right.
   - What Changed: Applied clip-path: inset(currentOffset px -5000px 0 -5000px). The top inset strictly hides rows above the menu, while the -5000px horizontal insets allow child flyouts (left or right) to remain 100% visible and interactive.

5. Direct Pointer Exit Cleanup (Batched React Commit):
   - Why: Moving the cursor directly from a child flyout onto the page body caused React to remove show from both child and parent simultaneously in a single commit, leaving parent menus with stuck negative marginTop, clipPath, or uncapped styles.
   - What Changed: Added explicit cleanup in the MutationObserver whenever a menu loses show, removing marginTop, clipPath, savedScrollTop, and inline overflow/max-height independently of ancestor traversal.

6. TypeScript Build Fix (Type Predicate Narrowing):
   - Why: isOpenDropdownMenu was declared as a type predicate (el is HTMLElement). In the batched close else branch, TypeScript subtracted HTMLElement from HTMLElement, narrowing target to never and failing the CI production build.
   - What Changed: Changed isOpenDropdownMenu to return a plain boolean, resolving compiler type-narrowing and ensuring clean production builds.
