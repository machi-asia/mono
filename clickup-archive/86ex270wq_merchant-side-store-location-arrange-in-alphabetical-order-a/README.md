Note for transparency — observed, but NOT a defect on this ticket

While testing we noticed the "No Store Locations Yet" empty state briefly appears on a store that does have locations, before the rows render. Including it for full transparency, but to be clear about what it is and isn't:

Where: /home/store-locations, during initial page load.
Cause: FetchAllStoreLocationRequest declares initialData: [], so isLoading is false on first paint and the table renders with zero rows; the '...Loading' placeholder is therefore never shown.
Measured: with a 50ms-interval probe over 4 runs, it appeared in all 4 — but as a single sub-second flicker in 3 of them, and ~1.9s in only 1. This was on a local dev server, which is slower than production.
Age: pre-existing since 2022 (Location.jsx dates to 2022-09-20; the initialData: [] line to 2022-11-30, commit 3bb5eff93).

Assessment: a real but minor, four-year-old cosmetic flicker that this ticket neither caused nor was scoped to fix — not "no issue," but equally not "an issue dev needs to fix" right now. It is a backlog-polish judgement call, and a reasonable call is to leave it alone. No action is requested of dev on this ticket. If ever picked up, it is a one-line change (drop initialData: [] so isLoading behaves as intended) and belongs in its own ticket.
